# 需求广场

员工在登录后从导航栏进入「需求广场」（`/demands`），发布业务需求、点击「我也需要」，或补充自己的使用场景。后续由负责人线下接手；本模块不包含开发认领、排期、交付和验收流程。

## 使用方式

1. 点击「发布需求」，填写需求标题、业务场景与痛点、期望结果。业务分类、发生频次、当前耗时、预计适用范围可选填。
2. 在广场按标题或场景搜索，按业务分类完整名称筛选，或勾选「我发布的」。支持最新发布和最多人需要排序。
3. 「我也需要」每个员工计一次，重复点击已支持按钮可撤回。发布和补充场景不会自动增加支持人数。
4. 在详情页补充场景，作者可以编辑自己的需求、编辑或删除自己的补充。
5. `SKILL_ADMIN` 和 `SUPER_ADMIN` 可以隐藏、恢复需求及补充内容。广场勾选「包含已隐藏需求」可找到待恢复内容。隐藏和恢复写入既有审计日志；普通员工不可通过直接链接读取隐藏内容。

业务分类为选填文本。频次、耗时与适用范围均为员工提供的信息，不自动评分，也不代表已验证的收益。

## 技术范围

- 数据库迁移：`V53__demand_square.sql` 新增 `demand`、`demand_support`、`demand_supplement` 三张表，不修改现有业务表结构。集成分支保留 V50 插件与 V51 提示词迁移，V52 为使用统计。
- API：`/api/web/demands`、`/api/v1/demands`，仅支持登录会话，写操作保留 CSRF 校验；不开放 API Token 调用。
- 查询：需求和补充分页，默认每页 20 条、上限 100 条；排序使用实际支持记录数，时间和 ID 作为稳定排序条件。
- 写入：锁定对应需求行后执行支持、撤回和内容修改，支持关系另有数据库唯一约束，保证并发重试不重复计数。
- 权限：需求及补充仅作者可修改；管理员只能执行隐藏、恢复操作，不能替作者编辑内容。
- 内容以纯文本展示，不执行用户输入的 HTML。
- 字数限制：标题 120、场景 4000、期望结果 2000、分类 80、频次及耗时各 200、适用范围 500、每条补充 4000。

## 运行与验证

在仓库根目录运行 `make dev-all`，登录后访问 `/demands`。后端启动时由 Flyway 执行新增迁移。API 变化后运行 `make generate-api`，不要手动修改生成的类型文件。

验证命令：

```bash
make test-backend-app
make typecheck-web
make lint-web
make test-frontend
cd web
pnpm exec playwright test e2e/demand-square.spec.ts --reporter=line
```

后端需求测试使用 Testcontainers 的独立 PostgreSQL，验证真实迁移、支持并发去重、权限、隐藏、分页排序和输入边界。页面测试覆盖发布、支持与撤回、补充的修改与删除、搜索和手机宽度。端到端测试会在目标本地开发数据库创建测试需求，请对独立测试数据库运行。

上线仍需执行项目部署回归及业务人工验收。应用回退不会删除新增需求表；已有数据应保留，不通过回退脚本自动删除。
